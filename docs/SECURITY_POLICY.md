## 정책 개요

### 1.1 목적

본 정보보안 정책은 Your Program 시스템과 관련된 모든 정보 자산을 보호하고, 정보보안 사고를 예방하며, 비즈니스 연속성을 보장하기 위해 수립되었습니다.

### 1.2 정책 원칙

#### 기밀성 (Confidentiality)
- 인가되지 않은 개인, 엔티티, 프로세스에 정보가 공개되지 않도록 보장
- 필요-지식 원칙(Need-to-know)과 최소 권한 원칙(Least privilege) 적용

#### 무결성 (Integrity)
- 정보와 처리 방법의 정확성과 완전성 보장
- 무단 변경, 파괴, 손실로부터 정보 보호

#### 가용성 (Availability)
- 인가된 사용자가 필요할 때 정보와 관련 자산에 접근할 수 있도록 보장
- 시스템 가동률 99.9% 이상 유지

### 1.3 정책 목표

**주요 목표:**
- 정보 자산의 기밀성, 무결성, 가용성 보장
- 법적, 규제적 요구사항 준수
- 비즈니스 연속성 및 재해 복구 능력 확보
- 보안 사고 예방 및 신속한 대응 체계 구축

**세부 목표:**
- Zero Trust 보안 모델 구현
- 실시간 위협 탐지 및 대응
- 데이터 분류 및 보호 체계 수립
- 정기적인 보안 감사 및 평가

## 보안 거버넌스

### 3.1 조직 구조

#### 정보보안위원회 (Information Security Committee)
**구성:**
- 위원장: 최고정보보안책임자(CISO)
- 위원: 각 부서 대표, IT 부서장, 법무팀장
- 간사: 정보보안팀장

**역할:**
- 정보보안 정책 승인 및 개정
- 보안 투자 계획 수립 및 승인
- 주요 보안 사고 대응 방향 결정
- 정기 보안 현황 검토

#### 정보보안팀 (Information Security Team)
**역할:**
- 보안 정책 수립 및 관리
- 보안 모니터링 및 사고 대응
- 보안 교육 및 인식 제고
- 보안 감사 및 평가

### 3.2 역할과 책임

#### 최고경영진 (C-Level)
- 정보보안 정책 최종 승인
- 보안 투자 의사결정
- 보안 문화 조성 리더십 제공

#### 부서별 책임
```
┌─────────────────────────────────────────────────┐
│ 부서            │ 주요 책임                    │
├─────────────────────────────────────────────────┤
│ IT 부서         │ 시스템 보안 구현 및 관리      │
│ 인사팀          │ 직원 보안 교육 및 인사보안    │
│ 법무팀          │ 컴플라이언스 및 계약 보안     │
│ 운영팀          │ 물리적 보안 및 시설 관리      │
│ 개발팀          │ 보안 코딩 및 애플리케이션 보안│
│ 품질보증팀      │ 보안 테스트 및 검증           │

## 접근 제어

### 4.1 사용자 인증

#### 인증 요구사항
- **강력한 비밀번호**: 최소 12자, 복잡성 요구사항 충족
- **다중 인증(MFA)**: 모든 특권 계정 및 원격 접속에 필수
- **생체 인증**: 고도의 보안이 요구되는 시스템에 적용

#### 비밀번호 정책
```
최소 길이: 12자
복잡성 요구사항:
- 대문자 1개 이상
- 소문자 1개 이상  
- 숫자 1개 이상
- 특수문자 1개 이상

금지사항:
- 사전 단어 사용 금지
- 개인정보 포함 금지
- 최근 5개 비밀번호 재사용 금지

변경 주기:
- 일반 사용자: 90일
- 특권 사용자: 60일
- 공유 계정: 30일
```

#### 계정 관리
- **계정 생성**: 정식 승인 절차 필수
- **계정 삭제**: 퇴사/전보 시 즉시 비활성화
- **휴면 계정**: 90일 미사용 시 자동 비활성화
- **특권 계정**: 분기별 검토 및 정당성 확인

### 4.2 권한 관리

#### 역할 기반 접근 제어 (RBAC)
```
┌─────────────────────────────────────────────────┐
│ 역할          │ 권한                           │
├─────────────────────────────────────────────────┤
│ System Admin  │ 시스템 전체 관리 권한           │
│ Security Admin│ 보안 설정 및 로그 관리          │
│ DB Admin      │ 데이터베이스 관리               │
│ Network Admin │ 네트워크 장비 관리              │
│ Developer     │ 개발 환경 접근                  │
│ Operator      │ 운영 모니터링                   │
│ Auditor       │ 감사 및 검토 (읽기 전용)        │
│ User          │ 기본 시스템 사용                │
└─────────────────────────────────────────────────┘
```

#### 최소 권한 원칙
- 업무 수행에 필요한 최소한의 권한만 부여
- 권한 상승은 임시적으로만 허용
- 정기적인 권한 검토 및 조정

#### 특권 계정 관리
- **특권 계정 목록**: 중앙 집중 관리
- **접속 기록**: 모든 특권 계정 활동 로깅
- **이중 인증**: 특권 계정 접속 시 필수
- **세션 모니터링**: 실시간 활동 감시

### 4.3 접근 통제

#### 네트워크 접근 통제
- **방화벽**: 모든 네트워크 경계에 설치
- **VPN**: 원격 접속 시 필수 사용
- **네트워크 분할**: DMZ, 내부, 관리 네트워크 분리
- **무선 보안**: WPA3 이상 암호화 적용

#### 물리적 접근 통제
- **출입 통제**: 카드키, 생체인증 시스템
- **방문자 관리**: 임시 출입증, 동행 원칙
- **CCTV**: 24시간 모니터링 및 90일 보관
- **보안 구역**: 서버실, 네트워크실 별도 관리

## 데이터 보호

### 5.1 데이터 분류

#### 분류 체계
```
┌─────────────────────────────────────────────────┐
│ 등급    │ 설명               │ 예시              │
├─────────────────────────────────────────────────┤
│ 최고기밀│ 공개 시 심각한 피해 │ 개인정보, 영업비밀 │
│ 기밀    │ 공개 시 상당한 피해 │ 내부 정책, 계약서  │
│ 내부전용│ 내부에서만 사용     │ 업무 문서, 이메일  │
│ 공개    │ 외부 공개 가능      │ 공개 자료, 매뉴얼  │
└─────────────────────────────────────────────────┘
```

#### 분류 절차
1. **데이터 소유자**가 생성 시점에 분류
2. **데이터 관리자**가 분류 적절성 검토
3. **분류 라벨**을 파일/시스템에 표시
4. **정기 검토**를 통한 분류 갱신

### 5.2 개인정보 보호

#### 수집 및 이용
- **수집 최소화**: 목적에 필요한 최소한의 정보만 수집
- **이용 제한**: 수집 목적 범위 내에서만 이용
- **동의 관리**: 명시적 동의 획득 및 관리
- **보존 기간**: 법정 보존 기간 준수

#### 처리 보안
```
암호화 요구사항:
- 전송 중: TLS 1.3 이상
- 저장 시: AES-256 이상
- 백업: 동일한 수준의 암호화

접근 제어:
- 역할 기반 접근 제어 적용
- 접근 로그 기록 및 모니터링
- 정기적인 접근 권한 검토
```

#### 개인정보 처리 시스템
- **개인정보 처리 현황 대장** 관리
- **개인정보 영향평가** 정기 실시
- **개인정보 처리 위탁 계약** 체결
- **개인정보 파기** 절차 준수

### 5.3 데이터 생명주기 관리

#### 생성 단계
- 데이터 분류 및 라벨링
- 접근 권한 설정
- 암호화 적용

#### 저장 단계
- 보안 저장소 사용
- 정기적 백업 수행
- 무결성 검증

#### 이용 단계
- 접근 로그 기록
- 무단 사용 모니터링
- 데이터 마스킹/익명화

#### 파기 단계
- 안전한 데이터 파기
- 파기 증명서 발급
- 복구 불가능 확인

## 시스템 보안

### 6.1 서버 보안

#### 보안 강화 (Hardening)
```
운영체제 보안:
- 불필요한 서비스 제거
- 보안 패치 정기 적용
- 안전한 설정 구성
- 로깅 및 모니터링 활성화

응용프로그램 보안:
- 보안 코딩 가이드라인 준수
- 입력값 검증 및 출력값 인코딩
- 세션 관리 강화
- 에러 처리 개선
```

#### 접근 보안
- **SSH 키 기반 인증**: 비밀번호 인증 비활성화
- **포트 변경**: 기본 포트 사용 금지
- **IP 허용 목록**: 필요한 IP만 접근 허용
- **세션 타임아웃**: 비활성 세션 자동 종료

#### 로그 관리
- **보안 이벤트 로깅**: 모든 인증, 권한 변경 기록
- **로그 보호**: 로그 파일 무결성 보장
- **중앙 집중 관리**: SIEM 시스템 연동
- **보존 기간**: 최소 1년 이상 보관

### 6.2 데이터베이스 보안

#### 접근 제어
- **데이터베이스 방화벽**: 불법 쿼리 차단
- **권한 분리**: 개발/운영/관리 권한 분리
- **암호화**: TDE(투명 데이터 암호화) 적용
- **접속 제한**: IP 기반 접속 제한

#### 데이터 보호
```
암호화 적용:
- 컬럼 단위 암호화 (민감 정보)
- 테이블스페이스 암호화
- 백업 파일 암호화

접근 모니터링:
- 모든 DB 접속 로깅
- 비정상 쿼리 탐지
- 권한 변경 알림
- 대용량 데이터 추출 모니터링
```

### 6.3 애플리케이션 보안

#### 보안 개발 생명주기 (SDLC)
```
1. 계획 단계:
   - 보안 요구사항 정의
   - 위협 모델링 수행

2. 설계 단계:
   - 보안 아키텍처 설계
   - 보안 설계 검토

3. 구현 단계:
   - 보안 코딩 가이드라인 적용
   - 정적 코드 분석

4. 테스트 단계:
   - 동적 보안 테스트
   - 모의해킹 테스트

5. 배포 단계:
   - 보안 설정 검토
   - 취약점 스캔 수행

6. 운영 단계:
   - 보안 모니터링
   - 보안 패치 적용
```

#### 웹 애플리케이션 보안
- **OWASP Top 10** 취약점 대응
- **입력값 검증**: 화이트리스트 방식 적용
- **세션 관리**: 안전한 세션 쿠키 설정
- **CSRF 보호**: 토큰 기반 검증

```

#### 방화벽 정책
- **기본 거부**: 명시적으로 허용하지 않은 모든 트래픽 차단
- **최소 개방**: 업무에 필요한 최소한의 포트만 개방
- **로깅**: 모든 차단 및 허용 로그 기록
- **정기 검토**: 분기별 방화벽 규칙 검토

### 7.2 무선 네트워크 보안

#### 무선랜 보안 설정
```
암호화: WPA3-Enterprise
인증: 802.1X + RADIUS
네트워크 분리: 
- 임직원용 (CORP)
- 손님용 (GUEST)  
- IoT 디바이스용 (IOT)

보안 설정:
- SSID 숨김 비활성화 (보안상 큰 효과 없음)
- MAC 주소 필터링 사용 안함
- 강력한 사전 공유 키 사용
```

#### 게스트 네트워크
- **분리된 VLAN**: 내부 네트워크와 완전 분리
- **인터넷 전용**: 내부 리소스 접근 차단
- **시간 제한**: 하루 단위 접속 제한
- **대역폭 제한**: 적절한 대역폭 할당

### 7.3 원격 접속 보안

#### VPN 보안
- **프로토콜**: IKEv2/IPSec 또는 OpenVPN
- **인증**: 인증서 + 2차 인증
- **암호화**: AES-256 + RSA-2048 이상
- **접속 로깅**: 모든 VPN 접속 기록

#### 원격 데스크톱 보안
- **다중 인증**: MFA 필수 적용
- **세션 암호화**: RDP over TLS
- **접속 제한**: 허용된 IP에서만 접속
- **세션 기록**: 화면 녹화 및 키로깅

## 사고 대응

### 8.1 보안 사고 대응 체계

#### 사고 대응팀 (CSIRT) 구성
```
┌─────────────────────────────────────────────────┐
│ 역할            │ 책임자              │ 연락처 │
├─────────────────────────────────────────────────┤
│ 팀장            │ CISO               │ 24/7   │
│ 기술 대응       │ 보안팀장           │ 24/7   │
│ 법무 대응       │ 법무팀장           │ 근무시간│
│ 홍보 대응       │ 홍보팀장           │ 24/7   │
│ 비즈니스 연속성 │ 운영팀장           │ 24/7   │
└─────────────────────────────────────────────────┘
```

#### 사고 분류 체계
```
심각도 1 (Critical):
- 시스템 완전 중단
- 대규모 개인정보 유출
- 금전적 손실 > 1억원

심각도 2 (High):
- 주요 서비스 장애
- 소규모 개인정보 유출  
- 금전적 손실 1천만~1억원

심각도 3 (Medium):
- 부분적 서비스 장애
- 내부 정보 유출
- 금전적 손실 100만~1천만원

심각도 4 (Low):
- 경미한 시스템 이상
- 스팸/피싱 메일
- 금전적 손실 < 100만원
```

### 8.2 사고 대응 절차

#### 1단계: 탐지 및 분석 (1시간 이내)
```
즉시 조치:
□ 사고 발생 확인 및 기록
□ 초기 영향 범위 파악
□ 관련자 비상 소집
□ 임시 조치 실시

수집 정보:
- 사고 발생 시간
- 영향받은 시스템/데이터
- 예상 피해 규모
- 공격자 정보 (가능한 경우)
```

#### 2단계: 격리 및 차단 (2시간 이내)
```
격리 조치:
□ 감염 시스템 네트워크 분리
□ 의심 계정 비활성화
□ 관련 서비스 일시 중단
□ 증거 보전 조치

차단 조치:
□ 공격 경로 차단
□ 방화벽 규칙 추가
□ IP 주소 블랙리스트 등록
□ 취약점 임시 패치
```

#### 3단계: 근절 및 복구 (8시간 이내)
```
근절 조치:
□ 악성코드 완전 제거
□ 취약점 패치 적용
□ 시스템 재설치 (필요시)
□ 보안 설정 강화

복구 조치:
□ 시스템 정상화
□ 데이터 복구
□ 서비스 재개
□ 모니터링 강화
```

#### 4단계: 사후 분석 (2주 이내)
```
분석 활동:
□ 근본 원인 분석
□ 대응 과정 평가
□ 피해 규모 산정
□ 재발 방지 대책 수립

문서화:
□ 사고 대응 보고서 작성
□ 교훈 사항 정리
□ 절차 개선 방안 도출
□ 관련 정책 업데이트
```

### 8.3 비즈니스 연속성 계획 (BCP)

#### 복구 목표 설정
```
┌─────────────────────────────────────────────────┐
│ 시스템           │ RTO    │ RPO    │ 우선순위 │
├─────────────────────────────────────────────────┤
│ 핵심 비즈니스 시스템│ 1시간  │ 15분   │ 1      │
│ 고객 서비스 시스템 │ 2시간  │ 30분   │ 2      │
│ 내부 업무 시스템   │ 4시간  │ 1시간  │ 3      │
│ 개발/테스트 시스템 │ 1일    │ 4시간  │ 4      │
└─────────────────────────────────────────────────┘

RTO: Recovery Time Objective (복구 목표 시간)
RPO: Recovery Point Objective (복구 지점 목표)
```

#### 대체 운영 계획
- **대체 사이트**: 재해 복구 센터 운영
- **데이터 백업**: 원격지 실시간 백업
- **통신 대안**: 다중 회선 및 위성 통신
- **인력 대안**: 재택근무 및 협력업체 활용
